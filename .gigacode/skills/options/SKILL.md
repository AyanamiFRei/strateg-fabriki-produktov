# Варианты (stage `options`)

**Знания:** `kb/methods/C-product-strategy.md` (C1 ядро стратегии, C2 каскад выбора, C4 генерация вариантов, C5 pre-mortem).
**Лимит:** ≤10 вызовов CLI, 1 вызов критика.

## Шаги
1. Сформулируй ≥3, обычно 4 варианта **для одной ситуации и одного горизонта**:
   - `O01` оставить как есть (честно: что будет без изменений, с цифрами базы);
   - 1–2 варианта развития разной глубины/стоимости (например, дешёвый сигнал vs полный продукт);
   - `O0n` закрыть направление (что экономим, что теряем, кто пострадает).
   Каждый — в **лучшей версии**, как его защищал бы сторонник. «Закрыть» не должен быть соломенным чучелом.
2. Для каждого: суть · кому и какую задачу решает · польза и охват · затраты и срок · что должно быть правдой (ключевые [A]) ·
   **сильнейшее возражение** · что его снимет · цена ошибки · критерий остановки.
3. Числа вариантов — через расчёты `analysis/Kxx.json` (`python st.py calc fns` — список функций; входы — ссылки на
   F/A через `"inputs"`). Литералы допустимы только для alpha, power, arms и т.п.
4. Таблица сравнения: строки — варианты, столбцы — одни и те же критерии; рекомендация агента и при каком значении
   ключевого допущения она меняется (порог из `flip`).
5. `projects/<p>/deliverables/options.md` (шаблон в `agent/templates/deliverables/`), заголовки `## O01 …`.
6. **Критик** (вызов 1 из 3): субагент `critic` с заданием «варианты» — или, если субагентов нет, отдельный проход по
   `agent/roles/critic.md`. Результат — `deliverables/critique.md` «возражение → якорь → что сделали». Внеси правки.
7. `python st.py stage done options` → код 3: покажи таблицу и рекомендацию, попроси выбрать.
   Допустимый ответ — «сначала проверить» (тогда выбор = вариант пилота). Затем `stage approve options --note "<выбор>"`.
