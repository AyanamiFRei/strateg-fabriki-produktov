# C. Продуктовая стратегия и экономика

## C1. Ядро хорошей стратегии (Румельт)
- Три части: **диагноз** (что мешает; критические факторы), **руководящая политика** (способ преодоления, а не цель), **согласованные действия** (ресурсы и шаги, исполняющие политику).
- Признаки плохой стратегии: набор целей без политики, расплывчатые «слова-пустышки», несогласованные цели, подмена проблемы результатом («низкое удержание» не диагноз, а симптом).
- Проверка: может ли политика отвергнуть что-то разумное? Если нет, это не политика.
- Каждое действие плана связано с диагнозом и политикой; висящие действия удалять.
Источник: https://fs.blog/a-primer-on-strategy/ [В]

## C2. Playing to Win (каскад выборов)
- Пять выборов: цель победы → где играть → как побеждать → необходимые способности → системы управления.
- Стратегия = выбор, что делать и чего не делать; «где» и «как» должны согласовываться.
- В стратегии продукта показать: выбранный сегмент и сценарий; отвергнутые сегменты и сценарии с причиной (осознанные отказы).
- Каскад итеративный: если способности (например, данные устройства) недоступны, пересмотреть «как побеждать».
Источник: https://fs.blog/playing-to-win-how-strategy-really-works/ [В]

## C3. Value proposition canvas
- Профиль клиента: задачи (jobs), боли (pains), выгоды (gains); карта ценности: продукты и услуги, обезболивающие, создатели выгод.
- Совпадение (fit) это гипотеза, пока клиенты не подтвердили; проверять каждую пару «боль → обезболивающее» по реальным свидетельствам.
- Писать для одного сегмента; для второй группы клиентов (собственные номера) отдельный профиль, переносить только проверенное.
- Альтернативы клиента из брифа: семейный чат, автоплатёж банка, приложение роутера, обращение в поддержку.
Источник: https://strategyzer.com/canvas/value-proposition-canvas [В]

## C4. Варианты: включать статус-кво и выход
- Минимум 3 содержательно разных варианта для одной ситуации и горизонта: «оставить как есть» (с прогнозом «без изменений»), «закрыть/не развивать направление», 1–2 действующих.
- Дешёвый вариант (например, предупреждение со ссылкой на существующую операцию) обязателен; дорогой оправдан только наблюдением, превышающим порог.
- Для каждого: польза, число клиентов, затраты, срок первых результатов, последствия ошибки, **сильнейшее возражение** (steel-man) и что его снимет.
- Факты, гипотезы и прогнозы в каждом варианте помечены по B1.
Источник: https://producttalk.org/opportunity-solution-tree [В; правило «≥3 решения»]

## C5. Pre-mortem
- После выбора варианта объявить «проект провалился через год» и каждому отдельно записать причины; затем собрать общий список по кругу.
- Классифицировать причины: допущение о спросе / данные / исполнение / согласие и безопасность / экономика.
- Превращать каждую причину в проверку, мониторинг или изменение плана; результат попадает в реестр рисков с наблюдаемым признаком.
- Метод опирается на «взгляд из будущего» (prospective hindsight) и снижает сверхуверенность.
Источник: https://comprobo24.github.io/assignments/performing_a_project_premortem.pdf [В; копия статьи Кляйна; оригинал HBR 2007/09 [П]: https://hbr.org/2007/09/performing-a-project-premortem]

## C6. Kill criteria (условия остановки)
- Задавать до запуска вместе с метриками успеха: метрика, порог провала, окно оценки, заранее решённое действие.
- Закреплять за названным владельцем продукта, а не только за разработкой.
- Решение принимается по порогу, а не по авторству идеи; учитывать текущие затраты на поддержку слабой функции.
- Для демо: двойное списание, показ чужих данных после отзыва согласия = немедленная остановка (бриф, стр. 11).
Источник: https://www.mindtheproduct.com/the-case-for-kill-criteria-in-product-management/ [В]

## C7. Юнит-экономика, LTV, окупаемость, порог безубыточности
- Дополнительная валовая прибыль = Σ(доп. оплаченные месяцы × ставка) + иные выгоды − новые прямые расходы. У каждого слагаемого объём, цена, период (бриф, стр. 9).
- Учебная ставка: 500 руб. за доп. месяц номера; работа, начатая в последнем месяце, даёт в году максимум 1 месяц на номер.
- LTV с вероятностью выживания: LTV = Σ_t [маржа_t × S_t / (1+d)^t], S_t вероятность оставаться платящим; при постоянных значениях m·r/(1+d−r). Брать чистую маржу, вычитать расходы на удержание; при нехватке данных давать условный расчёт.
- Порог: N_месяцев = (Цель − Прогноз без изменений + Новые расходы) / ставка. Пример брифа: (285−279)=6 млн / 500 = 12 000 доп. месяцев; расходы увеличивают порог.
- Окупаемость: накопленная доп. прибыль после прямых расходов по кварталам сравнивается с накопленными вложениями; до оценки разработки показать предельную сумму вложений за выбранный срок. Деньги после конца планового года относить к следующим годам.
- Ориентиры (SaaS, не телеком): окупаемость привлечения ~12 мес. верхняя граница, LTV:CAC выше 3; использовать только как справку.
- Сравнивать семьи одинакового размера (4 номера против 2 различаются уже числом номеров).
- Чувствительность: менять по одному входу (спрос, удержание, стоимость обслуживания) и показывать порог безубыточности; сценарии (основной/неблагоприятный) задаются набором согласованных допущений. Результат: «ломается при …», а не одно число.
Источники: https://www.forentrepreneurs.com/saas-metrics-2/ [В]; https://en.wikipedia.org/wiki/Customer_lifetime_value [В]; https://corporatefinanceinstitute.com/resources/knowledge/modeling/what-is-sensitivity-analysis [В]

## C8. Воронка, сведение потоков, инкрементальность
- Воронка: создана группа → приглашение принято → первое полезное действие в срок. Знаменатель всех шагов один: все созданные группы (пример брифа: 100 → 60 → 30 = 30 %, а не 50 %). Задать окно (14 дней от создания), единицу (группа, не человек) и порядок шагов.
- Показывать шаг потерь и его причину гипотезой; воронка говорит, где потеря, но не почему.
- Сведение потока: конец = начало + новые − выбывшие (+ реактивации), по каждой группе клиентов отдельно; расхождение больше допуска = ошибка определений, а не «шум».
- Один клиент, одно подключение: заранее задать правило атрибуции (приложение / поддержка), чтобы не было двойного счёта.
- Инкрементальность: эффект = результат у предложенных минус результат у группы сравнения; «приписанные» подключения завышают эффект.
- Стоимость дополнительного подключения = расходы канала / инкрементальные подключения; если прироста относительно обычного обслуживания не установлен, не считать.
- Не приписывать инициативе все подключения года: разрыв прогноза и цели закрывается и притоком, и снижением оттока.
Источники: воронка https://amplitude.com/guides/funnel-analysis [В]; сведение потока (идентичность «начало + движения = конец») https://help.chartmogul.com/hc/en-us/articles/4416682609426 [В]; инкрементальность https://support.google.com/google-ads/answer/14102450?hl=en-GB [В]
