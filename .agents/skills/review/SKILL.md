# Сборка и проверка (stage `review`)

**Знания:** `kb/methods/G-map-and-caveats.md` (чек-листы), `agent/rubrics/review.json`, `projects/<p>/traps.md`.

1. `python st.py check all` — жёсткие ошибки исправить; предупреждения — одна попытка исправить дешёвые.
2. **Критик** (вызов 2): субагент `critic` с заданием «итог» — рубрика, ловушки, 10 выборочных `python st.py why <ID>`
   (верно ли вывод следует из цитаты), согласованность продукта и коммуникаций, обещания vs функции. Без субагентов —
   отдельный проход по `agent/roles/critic.md`. Блокирующие возражения — исправить; остальные — ответить в critique.md.
3. `deliverables/summary.md` — резюме на 1 экран: рекомендация, почему, главное допущение и как его проверим,
   что решить человеку и к какому сроку, сколько стоит.
4. `python st.py report strategy` → `deliverables/STRATEGY.md` (легенда, разделы, «Откуда эти числа»);
   `python st.py check review`.
5. Запиши стоимость: `python st.py cost log …` за стадии без записи; `python st.py report run` → RUN_REPORT.md.
6. `python st.py stage done review` → код 3: покажи резюме (5–7 строк), спроси «принять / поправить что». После
   ответа — `stage approve review --note "…"`; правки → `stage reopen <стадия>`.
