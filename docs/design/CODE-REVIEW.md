# Code review и security review: Стратег (st.py, tools/strateg)

Дата: 2026-11-22. Роли: code-reviewer и security-reviewer (everything-claude-code). Объект: репозиторий целиком, код `tools/strateg/*.py`, документация (README, AGENTS.md, навыки), конфиги IDE. Файлы репозитория не менялись, кроме этого отчёта.

## Как проверялось

- Чистый клон в `/tmp/review-clone` (без `projects/.current`), Python 3.13, Linux.
- `python3 -m unittest discover -s tests`: 22 теста, OK, около 6 с.
- `python3 st.py validate`: 0 ошибок. `st.py --project demo-family resume` и `check all`: 0 нарушений.
- Буквальная команда из README `python st.py resume --project demo-family` падает (см. #10).
- Новый проект `init trial --from tests/fixtures/tiny/brief.md`, затем действия агента по AGENTS.md: `source add --note/--file`, `claim import` с плохой и хорошими строками, `calc run`, `stage done`, `resume`, `impact`, `decide`.
- Сеть: локальный HTTP-сервер в отдельном корне (`STRATEG_ROOT`, allowlist = `localhost`). Так проверены редиректы, robots.txt, инъекции и кодировки.
- Ограничения проверки. Сессия один раз перезапускалась, временный клон пропал, и сетевые тесты повторены в новом корне. На Windows ничего не запускалось: пункты с пометкой «Windows» найдены чтением кода. Пункты с пометкой «по коду» тоже не запускались, остальные воспроизведены. Проверка редиректов в `_fetch` для основного запроса работает: редирект на хост вне allowlist даёт код 2.

## Вывод

**Статус: блокировать (есть critical и high).** Архитектура разумная: реестр с дозаписью, расчёты через CLI, детерминированный пересчёт, разделение данных и инструкций. Тесты проходят, на демо-проекте `check all` чист. Слабое место в другом: заявленные гарантии держатся на допущениях, которые код не проверяет.

1. **Гарантии целостности обходятся тривиально.** И1 обходится правкой снимка, которую разрешает хук (#1). И2 обходится одним промежуточным [I] (#3). Ворота человека обходятся командой `stage done` для более поздней стадии (#4) и автоматическим разрешением `st.py allow/approve/accept` (#5). Тезисы README «проверяет код, а не модель» и «факт регистрируется, только если цитата найдена» сейчас неверны.
2. **Пакетный импорт, центральный путь записи, повреждает граф молча** (#2, #7, #8). Это хуже падения: `why` показывает правдоподобную, но ложную цепочку происхождения.
3. **Документированные сценарии ломаются:** «отзови → impact» (#6), исправление отклонённых строк по навыку collect (#9), создание расчётов в Claude Code (#11), первая команда README (#10).
4. **Безопасность.** Редиректы основного запроса проверяются корректно. Остались robots.txt (#17), чтение произвольных файлов (#12), выход slug за пределы `projects/` (#16), DoS в `arithmetic` (#14) и подделываемые маркеры недоверенных данных (#18). Захардкоженных секретов в репозитории нет (validate чист, `.env` в `.gitignore`).
5. **Windows** (не запускалось): главные риски — перекодировка stdin в хуках и MCP, CRLF и ложные «правки человека», расхождение `sync --python py` с `validate`.

Порядок исправления: сначала #1–#5 (инварианты и ворота), затем #6–#9 и #11 (рабочие сценарии), затем #12–#19. Для каждого исправления нужен регрессионный тест в `tests/test_e2e.py`; сценарии воспроизведения из таблицы подходят как основа.
