# Стратег Фабрики продуктов — описание работы

> Документ для жюри. PDF: `docs/STRATEGY-DESCRIPTION.pdf`; собирается из этого файла скриптом `docs/build_description_pdf.py`, скриншоты — `docs/build_screenshots.py`.

## 1. Что сделано

Репозиторий ИИ-агента в виде папки с инструкциями, базой знаний и CLI. Его открывают в AI-IDE (Cursor, Claude Code, Codex, GigaCode). Агент ведёт руководителя цифрового продукта от размытого запроса к трём результатам:
- проверяемая картина ситуации;
- не меньше трёх вариантов, включая «оставить как есть» и «закрыть»;
- согласованные продуктовая и коммуникационная стратегии с планом проверки.

После решения агент его сопровождает: хранит основания, отслеживает обязательства и пересматривает выводы при новых данных.

**Демо-проект:** `projects/demo-family`, бриф МегаФона «Связь для близких и собственных устройств». Итог: `deliverables/STRATEGY.md` (проверяемая версия) и `STRATEGY-reader.md` (версия для чтения).

## 2. Архитектура

```
              ┌───────────── модель IDE (мозг: читает, рассуждает, пишет тексты) ─────────────┐
 пользователь │ AGENTS.md (регламент) → навык стадии (.agents/skills) → kb/ (методика)        │
   (чат) ◄───►│                         │ черновики утверждений (inbox/*.jsonl), тексты     │
              │                         ▼                                                    │
              │  st.py (детерминированно): реестры · расчёты · проверки · состояние · стоимость │
              └───────────┬───────────────────────────┬──────────────────────────────┬─────┘
                          ▼                           ▼                              ▼
             evidence/ (снимки источников,   analysis/K*.json → *.out.json   state/ (task.json, журнал
             реестр F/A/H/P/I/Y с версиями)   (воспроизводимые расчёты)        с op_id, стоимость)
                          субагенты: critic (сильная модель) · source-reader · respondent (опции)
```

**Ключевая идея.** Всё, что должно быть воспроизводимым и проверяемым без доверия к модели, делает код:
- регистрация источников, снимков и цитат;
- расчёты;
- сверка чисел в текстах с расчётами;
- ворота стадий;
- журнал операций для возобновления;
- учёт стоимости.

Модель пишет тексты и рассуждает.

### 2.1. Процесс

| Стадия | Навык | Результат | Человек |
|---|---|---|---|
| постановка | intake | brief.md, глоссарий, ловушки, вопросы, меняющие решение (с порогами) | подтверждает |
| сбор | collect | источники S, факты F (цитата найдена в снимке) | — |
| диагноз | research | situation.md: известно / откуда / неизвестно; гипотезы H; сигнал ≠ причина | — |
| варианты | options + critic | options.md (≥3, «как есть», «закрыть»), critique.md | **выбирает** |
| стратегия | strategy | product_strategy.md, comms_strategy.md | — |
| план проверки | validation-plan | validation_plan.md | — |
| сборка | review + critic | STRATEGY.md, RUN_REPORT.md | **принимает** |
| сопровождение | after-decision | D, T, `due`, IMPACT при новых данных | при пересмотре |

Переход — `st.py stage done`. Коды возврата:
- **0** — можно идти дальше;
- **2** — нарушен жёсткий инвариант;
- **3** — нужен человек.

Агент задаёт не больше 3 вопросов за раунд, каждый — карточкой «вопрос · что разблокирует · варианты · что приму по умолчанию».

### 2.2. Знания и контекст — четыре слоя раздельно

| Слой | Где | Кто пишет |
|---|---|---|
| Постоянные инструкции | `AGENTS.md`, `agent/`, `.agents/skills/` | только человек (хуки и permissions запрещают модели) |
| Методические знания | `kb/methods/A…H` (≈45 методик с источниками), `kb/glossary.md` | только человек |
| Материалы проекта | `projects/<p>/materials`, `evidence/raw` (снимки с маркерами UNTRUSTED) | пользователь и `st.py` |
| Состояние задачи | `projects/<p>/state`, реестры JSONL, `analysis`, `decisions` | только `st.py` |

**Реестр утверждений.** Виды записей: F — факт, A — допущение, H — гипотеза, P — прогноз, I — вывод агента, Y — синтетика. У каждой записи есть версии, уверенность и связи `supports`, `contradicts`, `depends_on`, `derived_from`. Изменение — новая версия, старая остаётся в истории. Каждое число в документах имеет якорь.

**Жёсткие инварианты, проверяемые кодом:**
1. Факт — только с цитатой, найденной в снимке источника.
2. Синтетика — только поддержка гипотез, без процентов.
3. Число рядом с расчётом `[K]` совпадает с его результатом.
4. Принятое решение не редактируется.

[скриншот: check ловит подменённое число — код 2]

**Поиск:**
- *по формулировке* — BM25 с русским стеммером;
- *по смыслу* — глоссарий синонимов и перефразировки запроса от модели IDE, слияние через RRF;
- *по связям* — у каждого результата видны соседние записи.

Платная инфраструктура не нужна.

[скриншот: why K45 — цепочка числа до источника и формулы]

**Память между сеансами** — это сам реестр. Прежние выводы агента (I) и документы помечены как «не доказательство». Устаревшее исправляется (`supersedes`) или отзывается (`retract`), а зависимые записи уходят на пересмотр.

**Возобновление:** `st.py resume` выдаёт сводку примерно на тысячу токенов: стадия, ожидания от человека, прерванные шаги, частично импортированные пакеты («3 из 8»), правки человека, новые данные, сроки решений, стоимость. Повтор импорта не дублирует записи: у каждой операции свой `op_id`.

### 2.3. Компоненты

- **CLI `st.py`** (stdlib Python 3.10+, около 3,4 тыс. строк). Команды: `init`, `use`, `resume`, `status`, `source`, `claim`, `calc`, `check`, `stage`, `why`, `search`, `impact`, `decide`, `report`, `cost`, `allow`, `sync`, `validate`, `hook`, `mcp`, `judge`.
- **Расчёты** (`calc`, 21 функция): размер выборки для двух долей, DEFF, кластерная выборка, MDE, мощность, набор из конечной базы, интервал Ньюкомба, воронка, сведение потоков, окупаемость, предельные вложения, LTV, чувствительность и безопасная арифметика.
- **10 навыков** (формат SKILL.md, переносимы между IDE).
- **3 роли субагентов** с уровнем модели: critic — сильная, source-reader — дешёвая, respondent — средняя.
- **Хуки:**
  - SessionStart — сводка проекта;
  - Stop — обновление PROGRESS;
  - PreToolUse — запрет правки инструкций и прямой записи реестров, запрет curl и wget.

  Хуки только усиливают правила: те же правила проверяет код.
- **MCP-сервер** (stdio, только чтение): `resume`, `status`, `search`, `why`, `check`, `due`. Нужен для IDE с ограниченным терминалом.
- **Адаптеры** генерируются командой `st.py sync` из одного источника: CLAUDE.md, GIGACODE.md, `.claude/`, `.cursor/`, `.codex/`, `.gigacode/`, `.mcp.json`. Команда `sync --check` ловит расхождения.

### 2.4. Маршрутизация

- **Процесс:** правила в `config/models.json` («новый запрос → intake», «новые данные → after-decision», иначе — навык текущей стадии из `resume`).
- **Модель:** уровень задан в роли субагента. Генератор подставляет модель для каждой IDE.
- **Эскалация при сбое проверки:** детерминированная проверка → одна попытка исправить той же моделью → критик (сильная модель) → человек.
- **Jev (TypeSafe)** — опционально, для узких проверок «да/нет» по рубрике. Включается ключом. При сбое или низкой уверенности результат «не проверено» — пункт уходит критику, а не считается пройденным.

### 2.5. Безопасность

- Иерархия доверия описана в AGENTS.md: всё, что пришло из источников, — данные, а не инструкции.
- Снимки обёрнуты маркерами `<<<UNTRUSTED nonce>>>`. Детектор инъекций помечает подозрительный текст, агент показывает его пользователю.
- Загрузка из сети — только с доменов из allowlist. Проверяет код, расширить список может только человек.
- Секретов в репозитории нет — это проверяет `validate`. Ключ Jev задаётся только переменной окружения.
- Интервью — только с согласием (шаблон есть), без персональных данных. Наружу интервью не отправляются.

## 4. Ключевые промпты и инструкции

- `AGENTS.md` — регламент: иерархия доверия, начало сессии, стадии и ворота, как спрашивать, реестр и якоря, 4 инварианта, безопасность сбора, качество содержания, реплики пользователя, субагенты и стоимость.

## 6. Демо: время, расходы, ошибки и помощь человека

- **Время работы агента по журналу:** около 63 минут от `init` до записи решений. Сюда не входит ожидание субагентов-критиков (около 9 и 11 минут).
- **Стоимость:** около $4 по оценке через символы (`deliverables/RUN_REPORT.md`, таблица по стадиям). Это нижняя оценка: учтены не все промежуточные чтения. Субагенты-критики по счётчику платформы израсходовали около 370 тыс. токенов.
- **Человек:** 2 минуты — выбор направления и принятие результата. Постановка принята по умолчанию, это помечено в журнале.
- **Ошибки, которые нашла система:**
  - критик, проход 1: 3 блокирующие — неполная часть 4; пилот больше базы; правило Q01 срабатывало против выбора;
  - критик, проход 2: 2 блокирующие — несовместимые режимы контроля; ложные сигналы определены через успех;
  - слепой судья: неверная верхняя граница;
  - проверка `check`: 14 устаревших или неверных чисел по ходу работы.

  Всё исправлено. Журнал «что сделано» — в `critique.md`.

## 7. Заявленные возможности и ограничения

**Может:**
- вести задачу от запроса до стратегии с проверяемыми числами;
- возобновлять работу в новом чате или другой IDE;
- пересматривать выводы при новых данных;
- сопровождать решения.

Работает и на других задачах: тесты проходят на фикстуре другой отрасли (подписка на обеды).

**Ограничения:**
- Качество рассуждений зависит от модели IDE. На слабых моделях возможны ошибки формата JSONL — они ловятся при импорте, но требуют повторов.
- Учёт токенов — оценка. Точный расход вносится вручную из IDE.
- Числа в текстах сверяются с расчётами, но верность вывода из цитаты проверяет только критик, а не код. Сверка чисел — эвристика: допуски и разбор таблиц могут давать пропуски и ложные срабатывания.
- Запрет на подтверждения за человека принудительно работает в Claude Code (список `ask`). В других IDE он держится на инструкции и журнале.
- Загрузка веб-страниц ограничена allowlist. В изолированной среде демо открытые источники сохранены вручную как файлы с URL.
- Хуки работают в Claude Code и Cursor. В остальных средах безопасность держится на коде и инструкциях.
- Сравнение — один прогон на условие и один судья. Ручной аналитик не участвовал.
- Проверено на Windows 11 + Python 3.13 в OpenCode. Сквозной прогон в Cursor и GigaCode остаётся за командой: адаптеры для них генерируются и проверяются `validate`, но в этой среде эти IDE не установлены. Чек-лист — `docs/VIDEO.md`.
- GigaCode и Kodik проверены только по документации. Сквозной прогон в них — задача команды перед видео (чек-лист в `docs/VIDEO.md`).
