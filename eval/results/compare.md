# Сравнение: агент против обычного чата с ИИ

## Как сравнивали

- **Задача:** бриф МегаФона «Связь для близких и собственных устройств», один и тот же текст.
- **Обычный чат:** модель того же класса (Claude Opus 5.5, максимальный уровень рассуждений) получила бриф и задание «один документ из пяти частей». Один проход, без инструментов, поиска и скриптов. Результат: `blind/doc-Y.md`.
- **Агент:** этот репозиторий, полный процесс с воротами, реестром, расчётами, двумя проходами критика и выбором человека. Результат: `blind/doc-X.md` (STRATEGY.md на момент оценки).
- **Оценка:** слепой судья — отдельный экземпляр Opus 5.5 без сведений о происхождении. Рубрика R1–R13 (0–3 балла), плюс пересчёт по 8 чисел в каждом документе в Python. Полное заключение: `blind/judgement.md`.

## Где обычный чат выигрывает

1. **Цена и скорость.** Один проход примерно в 3–5 раз дешевле и в 3 раза быстрее.
2. **Читаемость.** Ближе к языку руководителя: даты, порядок частей брифа, нет служебных якорей.
3. **Полнота по букве брифа.** Прогноз по каналам привлечения, ценность группы на 3 года.
4. **Арифметика.** В этом прогоне без ошибок. Агент ошибся в верхней границе вклада удержания: описание и формула расходились.

## Где агент выигрывает

1. **Проверяемость.** Любое число ведёт к источнику с цитатой или к названному допущению. Расхождение числа с расчётом блокируется кодом.
2. **Глубина выбора.** Пять вариантов, включая настоящее «закрыть», и сильнейшее возражение у каждого.
3. **Самокоррекция.** Независимый критик нашёл в первом проходе 3 блокирующие ошибки агента, во втором — ещё 2. Пример: пилот требовал больше групп, чем есть в базе. Обычный чат такой проверки не делает.
4. **Жизнь после решения.** Возобновление, пересмотр при новых данных с пересчётом «было → стало», решения со снимком реестра, обязательства и сроки.

## Что исправлено после оценки (повторно не оценивалось)

- Верхняя граница пересчитана согласованно: около 5,8 млн руб., но только при заведомо невыполнимых условиях. Реалистично — около 44 тыс. руб. Вывод «инициатива не закрывает разрыв прибыли» сохранился, теперь с честным обоснованием.
- «Непроверяемые» числа: таблица «Откуда эти числа» стала транзитивной и показывает значения всех входов расчётов, включая допущения.
- Читаемость: `report strategy` дополнительно собирает `STRATEGY-reader.md` — версию для руководителя без служебных якорей. Числа в ней те же.
- Добавлены прогноз по каналам привлечения и полные правила решения по интервалу, которые покрывают и исход «около нуля».

## Ограничения сравнения

- По одному прогону на условие и один судья. Это пример, а не статистически значимая оценка.
- Судья той же семьи моделей, что и оба исполнителя. Якоря выдают «агентный» документ, поэтому слепота неполная.
- Ручной аналитик не участвовал: у команды не было времени на 4-часовой ручной прогон.
- Учёт токенов агента — оценка по символам (`config/cost.json`). Точный расход в IDE вносится командой `cost log --basis reported`.

**Вывод.** Если нужна быстрая читаемая записка, обычный чат дешевле и почти не хуже. Агент оправдывает себя там, где руководителю нужно проверять числа, возвращаться к работе, пересматривать выводы при новых данных и отслеживать решения. Это и есть сценарий «Фабрики продуктов». За это приходится платить в 3–5 раз большим расходом.
